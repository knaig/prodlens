Why it exists

Vibe-coded UIs quietly rot

A button renders but does nothing. A link points at a route that no longer exists. A screen was designed but never wired into navigation. Normal dev loops check "does this one flow work" - nothing checks "is every edge functional across the whole graph." That gap is exactly what this tool tests.

Dead button
onClick wired to nothing, or a server action never imported into the page.
Broken link
Href targets a route that was renamed or deleted after a refactor.
Unreachable screen
A page exists in the router but no edge in the app navigates to it.

Built for apps where changes move fast and checking every screen by hand is impossible.

The core model

Your UI, as a graph

Screens are nodes, transitions are edges. Everything downstream - prioritization, execution, reporting - operates on this graph, so a finding is always grounded in a real screen + real interaction.

Node
A screen: a route pattern like /[project]/studio, carrying its URL and a state signature.
->
Edge
An action that goes somewhere: click "Save", a link, a navigation. Status: working / broken / untested.
->
Finding
Unreachable screens, dead ends, missing return paths, broken edges, dead elements - each tied back to its node.
working edge broken edge unreachable / dead end
Discovery: two complementary passes

No browser, then a browser

1. Static pass - ts-morph
Parses the app source. No browser, no server, no flakiness. Builds the route inventory and classifies every interactive element: navigates, server-action, local-state, or dead.
+
2. Live crawl - Playwright
BFS from entry points, reads the real rendered hrefs (resolves template literals and runtime redirects), clicks buttons, records what actually happens. Authenticates once, caches the session.
Why two
Static finds what the code looks like it does in seconds. Live confirms what it actually does. Merged together, they beat either alone.
Merge & analyze

One graph, one verdict per screen

The two passes merge into a single graph that is versioned (GraphVersion). Route matching is specificity-aware: /[project]/studio/new wins over /[project]/studio/[id] because its literal segments outnumber them.

Unreachable
No incoming edge from any live click.
Dead end
No outgoing edges after it.
Missing return
Forward nav works, but nothing navigates back.
Broken edge
Action ran in a browser; page did not navigate.
Prioritization engine

Personas and journeys that matter

From the recovered graph, the synthesis engine infers personas and proposes prioritized journeys. Every step in a journey is grounded in a real edge (found by BFS to the target), never free text - so execution can replay it deterministically.

Personas
Who uses the app: new visitor, returning customer, power user. LLM-inferred with ANTHROPIC_API_KEY, heuristic fallback otherwise.
Journeys
Critical paths per persona: signup, onboarding, core value loop - ranked by risk.
Grounded steps
Each step = a real graph edge + (where a form exists) a heuristic InputScenario to fill first.
offline learning loop (GEPA) feeds prior run feedback into the next plan
Execution engine

Replays the plan, records reality

01reviewManual gate: approve, reject, or edit each journey before it runs.
02runBounded-concurrency Playwright workers replay approved paths against the live app.
03formsDetected input clusters are filled like a user before submit - disabled-until-valid is not misread as broken.
04agent fallbackA step the DOM can't resolve gets re-clicked by an LLM agent that picks the best-matching element.
The run emits its own observed graph alongside the intended one - that diff is the report.
Report & explore

Diff intended vs actual

The report compares the intended graph against what execution actually observed, ranks findings by severity, and appends run feedback for the learning loop. The explorer is a single self-contained explorer.html - no server, open it directly.

Intended
The plan
Graph + prioritized journeys, saved as a version before running.
Actual
What really happened
Observed edges, pass/fail per step, screenshots, per-path videos.
Diff
The report
Broken edges, missing return paths, dead ends - ranked by severity, exit code CI-friendly.
